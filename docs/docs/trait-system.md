# Trait System

In **ingot**, behaviors for blocks and items are defined using C# interfaces called **traits**. Instead of writing verbose JSON components, you implement strongly-typed interfaces on your content classes (or block permutations). The library discovers these interfaces at compile time via reflection and serializes the correct `minecraft:*` components into the output JSON.

Most traits are automatically generated from the official Minecraft Bedrock documentation using the [`ingot.Generators.TraitGenerator`](https://pyroboots.github.io/ingot/api/ingot.Generators.TraitGenerator.html). A small number of frequently-used properties (such as `minecraft:display_name`, `minecraft:friction`, `minecraft:light_emission`, etc.) are exposed as convenient virtual properties directly on the `Block` and `Item` base classes instead of requiring a trait.

## Using Traits

To add behavior to a block or item, simply have your class implement the desired trait interfaces:

```csharp
using ingot.Core.Behaviour.Block;
using ingot.Core.TraitSystem.Traits.Block;

public class MyBlock : Block, IDestructibleByMining, IGeometry, ITick
{
    // ... required members
}
```

```csharp
using ingot.Core.Behaviour;
using ingot.Core.TraitSystem.Traits.Item;

public class MyItem : Item, IFood, IDurability
{
    // ...
}
```

Traits can also be applied to [block permutations](block-permutations.md) so that certain components only appear under specific conditions.

## Implementing Trait Properties

Trait interfaces expose properties. Because a class may implement many traits, and to avoid name clashes with properties on base classes, **explicit interface implementation** is the recommended and most common pattern:

```csharp
using ingot.Core.Behaviour;
using ingot.Core.Common;
using ingot.Core.TraitSystem.Traits.Item;

public class LasagnaItem : Item, IFood, IBlockPlacer
{
    public override Identifier Identifier => new("test:lasagna");
    public override string Texture => "lasagna";

    // Explicit implementations for the trait properties
    int IFood.Nutrition => 5;
    float IFood.SaturationModifier => 0.9f;
    string IFood.UsingConvertsTo => "minecraft:bowl";

    dynamic IBlockPlacer.Block => "test:block_of_dense_lasagna";
    bool IBlockPlacer.ReplaceBlockItem => true;
}
```

> [!NOTE]
> Some trait properties are `abstract` (you **must** provide a value) because they have no default and others are `virtual` (you only override them when you need to change the behavior) with defaults from the MS Docs - if they are autogenerated.

You can also use implicit implementation if the names do not conflict:

```csharp
public int Nutrition => 5;           // satisfies IFood.Nutrition
public float SaturationModifier => 0.9f;
```

## How the Trait System Works

1. When `Block.Compile(Type)`, `Item.Compile(Type)`, or `BehaviourPack` compilation runs, `TraitSystem.GetTraits(...)` is called on the concrete type.
2. It enumerates all interfaces implemented by the type.
3. For each interface that carries a `[Trait("minecraft:xxx", TraitType.Block/Item)]` attribute, a `Trait` entry is created.
4. Every property on that interface decorated with `[TraitProperty]` (or `[TraitProperty("path")]`) is inspected.
5. The getter is invoked on a temporary instance of your class to obtain the current value.
6. Values are written under the component using `PascalToSnakeCase` conversion for the JSON keys (e.g. `SecondsToDestroy` → `seconds_to_destroy`).
7. The resulting object is emitted inside the `components` section of the generated JSON.

Example output for a destructible block trait:

```json
"minecraft:destructible_by_mining": {
    "seconds_to_destroy": 2.5,
    "item_specific_speeds": [ ... ]
}
```

**Compile-time safety and feedback**:
- The `CompilerState` system emits warnings when values are null/empty, when block states exceed 16 permutations, when a trait is used on the wrong content type, etc.
- A full log is written to `{outputDir}/ingot.log` (e.g. `./output/ingot.log`) when using `Pack.Compile(..., verbose: true)` (the default).

## Trait Attributes (Advanced)

- `[Trait(string identifier, TraitSystem.TraitType constraint)]` - placed on the interface. Declares the Minecraft component name and whether the trait is valid on blocks, items, or entities.
- `[TraitProperty]` or `[TraitProperty("some.nested.path")]` - placed on properties inside the trait interface. The (optional) path controls where the value is written in the generated component object. Currently most traits use the default `"@=*"` (place directly under the component).

## Block vs Item vs Entity Traits

| Category     | Tag Interface    | TraitType     | Notes                              |
|--------------|------------------|---------------|------------------------------------|
| Blocks       | `IBlockTrait`    | `Block`       | Used on `Block` and `BlockPermutation` |
| Items        | `IItemTrait`     | `Item`        | Used on `Item`                     |
| Entities     | `IEntityTrait`   | `Entity`      | (Work in progress - not documented yet) |

See the API reference for the full list of available traits:
- [Block Traits](https://pyroboots.github.io/ingot/api/ingot.Core.TraitSystem.Traits.Block.html)
- [Item Traits](https://pyroboots.github.io/ingot/api/ingot.Core.TraitSystem.Traits.Item.html)

## Creating New Traits

New traits are normally generated by running the generator against the official Microsoft docs pages:

```bash
dotnet run --project ingot.Generators
```

By default this regenerates trait interfaces into `ingot.Core/TraitSystem/Traits/Block/` and `ingot.Core/TraitSystem/Traits/Item/`. Pass custom output directories as optional CLI arguments if needed. You can also write custom traits by hand:

1. Create an interface in the appropriate `Traits.Block` / `Traits.Item` folder.
2. Decorate it with `[Trait("minecraft:your_component", TraitSystem.TraitType.Block)]`.
3. Inherit from `IBlockTrait` or `IItemTrait`.
4. Add properties with `[TraitProperty]` and XML documentation.
5. Implement the logic in your content class.

After adding a hand-written trait, make sure to also handle any special serialization needs inside `Trait.Compile` if the component structure is not a flat set of properties.

## Summary

The trait system lets you compose block and item behavior using ordinary C# interface inheritance. It keeps your addon code readable, refactorable, and type-safe while still producing the exact JSON format that Minecraft Bedrock expects.
