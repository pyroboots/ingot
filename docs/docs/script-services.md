# Script Services and Events

**ingot** supports two pack-level Script API entry points in addition to [block](block/block-events.md) and [item](item/item-events.md) custom components:

| Feature | Registration | Output | When it runs |
|---------|--------------|--------|--------------|
| **Services** | `pack.AddService(...)` | `bp/scripts/services/` | Recurring tick interval via `system.runInterval` |
| **Script events** | `pack.AddScriptEvent(...)` | `bp/scripts/events/` | When `/scriptevent namespace:name` is received |

Both require `ScriptsEnabled = true` and are imported from generated `bp/scripts/main.js`.

```csharp
pack.ScriptsEnabled = true;
pack.AddService("./scripts/services/tick_service.js");
pack.AddScriptEvent("mypack:hello", """
    world.sendMessage(event.message);
    """);
pack.Compile("./output");
```

> [!IMPORTANT]
> Services and script events require `ScriptsEnabled = true`. Without it, registrations are ignored and ingot emits a compile-time warning.

## Services

**Services** are Script API scripts that run on a recurring tick interval. They are intended for timers, global state, or world scans.

```csharp
pack.ScriptsEnabled = true;
pack.AddService("./scripts/services/tick_service.js");
pack.Compile("./output");
```

By default, services run **every tick** (`intervalTicks: 1`). Pass a higher value to run less often:

```csharp
pack.AddService("./scripts/services/slow_service.js", intervalTicks: 20);
```

### Writing a Service

> [!TIP]
> A service source file contains only the **tick handler body** - the code that should run each interval. You do not write `system.runInterval` yourself; ingot wraps your body automatically:

```javascript
for (const player of world.getAllPlayers())
    player.onScreenDisplay.setActionBar("Service running");
```

At compile time, ingot generates `bp/scripts/services/tick_service.js`:

```javascript
// autogenerated by ingot

import { system, world } from "@minecraft/server";

system.runInterval(() => {
for (const player of world.getAllPlayers())
    player.onScreenDisplay.setActionBar("Service running");
}, 1);
```

With `intervalTicks: 20`, the closing line becomes `}, 20);` instead.

The generated file is imported from `bp/scripts/main.js`.

`system` and `world` are imported in the wrapper, so your service body can use them directly. For other Script API types, add imports to a separate module and import that module from your service body, or use the fully qualified global if your project setup exposes it.

### `AddService` parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `sourceFile` | `string` | - | Path to the JavaScript tick handler body. |
| `name` | `string?` | source file name | Output file name under `bp/scripts/services/`. |
| `intervalTicks` | `int` | `1` | Ticks between each invocation. Must be at least 1. |

## Script Events

**Script events** bind a handler body to a Minecraft `/scriptevent` id. When something runs `/scriptevent mypack:hello some message`, the Script API fires `system.afterEvents.scriptEventReceive` and your body runs if the id matches.

### Inline handlers

`ScriptHandler` accepts a raw JavaScript string (implicit conversion):

```csharp
using ingot.Core.Scripting;

pack.ScriptsEnabled = true;
pack.AddScriptEvent("mypack:hello", """
    world.sendMessage(event.message);
    """);
```

### File-based handlers

```csharp
pack.AddScriptEvent(
    "mypack:hello",
    ScriptHandler.FromFile("./scripts/events/hello.js"));
```

> [!TIP]
> The file should contain only the **handler body**. The `event` parameter is in scope (`event.id`, `event.message`, `event.sourceEntity`, and other Script API fields).

```javascript
world.sendMessage(event.message);
```

### What Gets Generated

For `AddScriptEvent("mypack:hello", ...)` with the default output name, ingot writes `bp/scripts/events/mypack_hello.js`:

```javascript
// autogenerated by ingot

import { system, world } from "@minecraft/server";

system.afterEvents.scriptEventReceive.subscribe((event) => {
    if (event.id !== "mypack:hello") return;
    world.sendMessage(event.message);
});
```

The file is imported from `bp/scripts/main.js`.

### `AddScriptEvent` parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `eventId` | `string` | - | Script event id in `namespace:name` form (e.g. `mypack:hello`). |
| `handler` | `ScriptHandler` | - | Handler body (inline string or `ScriptHandler.FromFile`). Must be configured. |
| `name` | `string?` | derived | Output file name under `bp/scripts/events/`. Defaults to the source file name when file-based, otherwise `{namespace}_{name}.js` from `eventId`. A `.js` suffix is added if missing. |

## Services vs Script Events vs Block/Item Events

| Feature | Block/Item Events | Services | Script Events |
|---------|-------------------|----------|---------------|
| Registration | `BlockEvents` / `ItemEvents` on content classes | `pack.AddService(...)` | `pack.AddScriptEvent(...)` |
| Source contents | Handler body for one custom-component event | Tick handler body | `/scriptevent` handler body |
| Wrapping | Custom component registration | `system.runInterval(..., intervalTicks)` | `scriptEventReceive` subscribe + id filter |
| Output path | `bp/scripts/blocks/` or `bp/scripts/items/` | `bp/scripts/services/` | `bp/scripts/events/` |
| Trigger | Player/world interaction on that content | Every N ticks | `/scriptevent id` (commands, other scripts, etc.) |

## Appending to `main.js`

For one-off startup code (not a recurring service, not a `/scriptevent` handler, and not a custom component event), set `Pack.ScriptEntryBody`. The resolved body is written at the end of generated `bp/scripts/main.js` **after** event, service, and script-event imports:

```csharp
using ingot.Core.Scripting;

pack.ScriptsEnabled = true;
pack.AddService("./scripts/services/tick_service.js"); // or any event-bearing content
pack.ScriptEntryBody = """
    console.log("pack scripts loaded");
    """;
// or: pack.ScriptEntryBody = ScriptHandler.FromFile("./scripts/bootstrap.js");
```

> [!NOTE]
> `ScriptEntryBody` is only written when `ScriptsEnabled` is `true` **and** the script registry already has entries (block/item events, services, and/or script events). It does not create a script pack by itself.
