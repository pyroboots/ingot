# Block Events (Script API)

**ingot** can generate [Minecraft Bedrock Script API](https://learn.microsoft.com/minecraft/creator/documents/scripting/overview) custom block components from C#. Instead of hand-writing JavaScript registration code and manually wiring components into block JSON, you declare event handler bodies on your block class and the compiler does the rest.

Block events are configured through the `BlockEvents` struct on `Block`.

## Prerequisites

Block event generation requires Script API support to be enabled on your pack:

```csharp
pack.ScriptsEnabled = true;
pack.Compile("./output");
```

If a block defines handlers but `ScriptsEnabled` is `false`, **ingot** emits a compile-time warning and skips script generation.

The behaviour pack only receives a script module in `manifest.json` when there is at least one script to load (block/item events or [services](script-services.md)). Setting `ScriptsEnabled = true` alone does not create an empty script pack.

You can also configure the script entry point and module dependencies on `Pack`:

| Member              | Type                          | Default                    | Description |
|---------------------|-------------------------------|----------------------------|-------------|
| `ScriptsEnabled`    | `bool`                        | `false`                    | Enables Script API script generation during compile. |
| `ScriptEntry`       | `string`                      | `"scripts/main.js"`        | Entry script referenced by the behaviour pack manifest. |
| `ScriptApiModules`  | `Dictionary<string, Version>` | `@minecraft/server` 2.8.0  | Module dependencies written to `manifest.json` and imported by `main.js`. |

## Basic Usage

Override `BlockEvents` on your block class. Each property is a `ScriptHandler` containing the **body** of a JavaScript event handler — the code inside the handler function, not a full function declaration.

### Inline handlers

```csharp
using ingot.Core.Behaviour.Block;
using ingot.Core.Common;

public class PressurePlateBlock : Block
{
    public override Identifier Identifier => new("mynamespace:pressure_plate");

    public override MaterialInstances MaterialInstances => new()
    {
        All = new MaterialInstance("pressure_plate", MaterialInstance.RenderMethods.Opaque)
    };

    public override BlockEvents? BlockEvents => new()
    {
        OnPlaceEvent = """
            event.dimension.playSound("random.click", event.block.location);
            """,
        PlayerInteractEvent = """
            const player = event.player;
            player.sendMessage("You stepped on the plate!");
            """
    };
}
```

Raw JavaScript strings still work because `ScriptHandler` defines an implicit conversion from `string`.

### File-based handlers

For larger handlers, load the body from a `.js` file:

```csharp
using ingot.Core.Scripting;

public override BlockEvents? BlockEvents => new()
{
    OnPlaceEvent = ScriptHandler.FromFile("./scripts/blocks/pressure_plate_on_place.js"),
};
```

The file should contain only the handler body:

```javascript
event.dimension.playSound("random.click", event.block.location);
```

Register and compile as usual:

```csharp
using ingot.Core;

Pack pack = Pack.Create(Guid.NewGuid().ToString(), "My Addon", "Blocks with script events")
    .AddBlock<PressurePlateBlock>();

pack.ScriptsEnabled = true;
pack.Compile("./output");
```

For global tick logic, use [services](script-services.md) via `pack.AddService(...)`.

## What Gets Generated

For a block with identifier `mynamespace:pressure_plate` and at least one event handler, **ingot** produces three things:

### 1. Custom component in block JSON

An empty component is added to the block's `components` object. The component id is derived from the block identifier:

```
mynamespace:pressure_plate_block_events_component
```

```json
"components": {
    "mynamespace:pressure_plate_block_events_component": {}
}
```

### 2. Per-block JavaScript file

A script file is written under the behaviour pack:

```
bp/scripts/blocks/mynamespace_pressure_plate_events.js
```

This file registers the custom component at startup:

```javascript
// autogenerated by ingot
import { system } from "@minecraft/server";

const MynamespacePressurePlateBlockEventsComponent = {
    onPlace(event) {
        event.dimension.playSound("random.click", event.block.location);
    },
    onPlayerInteract(event) {
        const player = event.player;
        player.sendMessage("You stepped on the plate!");
    },
};

system.beforeEvents.startup.subscribe(({ blockComponentRegistry }) => {
    blockComponentRegistry.registerCustomComponent(
        "mynamespace:pressure_plate_block_events_component",
        MynamespacePressurePlateBlockEventsComponent
    );
});
```

### 3. Updated `main.js` entry point

**ingot** writes `bp/scripts/main.js` with imports for your configured Script API modules, [services](script-services.md), and every generated block/item event script:

```javascript
// autogenerated by ingot
import "@minecraft/server";
import "./blocks/mynamespace_pressure_plate_events.js";
```

The behaviour pack manifest references `scripts/main.js` as the script module entry when scripts are present.

## Available Events

Each `BlockEvents` property maps to a Script API custom component event name. Set a property to `null` (or omit it) to skip that handler.

| C# Property             | Script API Event      | Notes |
|-------------------------|-----------------------|-------|
| `EntityFallOnEvent`     | `onEntityFallOn`      | Works best with `minecraft:entity_fall_on`. Requires a tall enough `minecraft:collision_box`. |
| `OnPlaceEvent`          | `onPlace`             | Fires when the block is placed or snow-logged. |
| `PlayerBreakEvent`      | `onPlayerBreak`       | Fires when a player breaks the block. |
| `PlayerInteractEvent`   | `onPlayerInteract`    | Not called when interacting with an empty bucket. |
| `PlayerPlaceBeforeEvent`| `beforeOnPlayerPlace` | Runs before client-side placement; can cancel placement. |
| `RandomTickEvent`       | `onRandomTick`        | Fires on random ticks. |
| `RedstoneUpdateEvent`   | `onRedstoneUpdate`    | Requires `minecraft:redstone_consumer` to trigger reliably. |
| `StepOffEvent`          | `onStepOff`           | Requires a tall enough `minecraft:collision_box`. |
| `StepOnEvent`           | `onStepOn`            | Requires a tall enough `minecraft:collision_box`. |
| `TickEvent`             | `onTick`              | Requires `minecraft:tick`. |
| `BlockStateChangeEvent` | `onBlockStateChange`  | Fires when the block permutation changes. |
| `EntityEvent`           | `onEntity`            | Fires when an entity executes an event on the block. |

Handler bodies are inserted verbatim into the generated JavaScript. Use valid Script API syntax and the `event` parameter provided by each hook.

## Pairing Events with Traits

Some Script API events only fire when the block also has the matching vanilla component. Add the appropriate [trait](trait-system.md) on your block class:

```csharp
using System.Numerics;
using ingot.Core.TraitSystem.Traits.Block;

public class FallDamageBlock : Block, IEntityFallOn, ICollisionBox
{
    // ...

    public override BlockEvents? BlockEvents => new()
    {
        EntityFallOnEvent = """
            event.entity.applyDamage(2);
            """
    };

    float IEntityFallOn.MinimumFallDistance => 2f;
    Vector3 ICollisionBox.Size => new(16, 24, 16);
}
```

Common pairings:

| Event property        | Recommended trait(s)        | Component |
|-----------------------|-----------------------------|-----------|
| `EntityFallOnEvent`   | `IEntityFallOn`             | `minecraft:entity_fall_on` |
| `RedstoneUpdateEvent` | `IRedstoneConsumer`         | `minecraft:redstone_consumer` |
| `TickEvent`           | `ITick`                     | `minecraft:tick` |
| `StepOnEvent` / `StepOffEvent` / `EntityFallOnEvent` | `ICollisionBox` | `minecraft:collision_box` (must be taller than 3.2 pixels on Y) |

**ingot** emits compile-time warnings when an event handler is configured without its recommended trait. It does not auto-add traits. If the required component is missing, the handler will not fire in-game.

## How Compilation Works

Script generation is a dedicated pass that runs after behaviour-pack JSON is written:

1. During `Block.Compile`, if `BlockEvents.HasEvents` is `true`, the custom component name is written into the block's `components` object.
2. After `BehaviourPack.Compile` finishes, **ingot** scans all registered blocks and items, validates trait pairings, generates per-content scripts, wraps [services](script-services.md) to run every tick, and writes `scripts/main.js`.
3. The behaviour pack manifest includes a script module only when at least one script file was produced.

Block events require compiling through `Pack.Compile(...)`. Calling `Block.Compile(typeof(MyBlock))` in isolation writes JSON only when pack context is available.

## Tips & Gotchas

- `BlockEvents` is a `struct`. Use `new()` with an object initializer as shown above.
- Only properties you set are included in the generated component. An empty `BlockEvents` value is ignored.
- Each block with events gets its own `.js` file and its own custom component id.
- `scripts/main.js` is regenerated on every compile from events, services, and configured module imports.
- Multi-line handlers work well with C# raw string literals (`""" ... """`) or `ScriptHandler.FromFile(...)`.
- Enable `pack.Compile("./output", verbose: true)` to see script messages and trait warnings in `ingot.log`.
