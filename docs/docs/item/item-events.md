# Item Events (Script API)

**ingot** can generate [Minecraft Bedrock Script API](https://learn.microsoft.com/minecraft/creator/documents/scripting/overview) custom item components from C#. Instead of hand-writing JavaScript registration code and manually wiring components into item JSON, you declare event handler bodies on your item class and the compiler does the rest.

Item events are configured through the `ItemEvents` struct on `Item`.

## Prerequisites

Item event generation requires Script API support to be enabled on your pack:

```csharp
pack.ScriptsEnabled = true;
pack.Compile("./output");
```

> [!WARNING]
> If an item defines handlers but `ScriptsEnabled` is `false`, ingot emits a compile-time warning and **skips script generation**.

> [!NOTE]
> The behaviour pack only receives a script module when at least one script exists (events or [services](../script-services.md)).

You can also configure the script entry point and module dependencies on `Pack`:

| Member              | Type                          | Default                    | Description |
|---------------------|-------------------------------|----------------------------|-------------|
| `ScriptsEnabled`    | `bool`                        | `false`                    | Enables Script API script generation during compile. |
| `ScriptEntry`       | `string`                      | `"scripts/main.js"`        | Entry script referenced by the behaviour pack manifest. |
| `ScriptApiModules`  | `Dictionary<string, Version>` | `@minecraft/server` 2.8.0  | Module dependencies written to `manifest.json` and imported by `main.js`. |
| `ScriptEntryBody`   | `ScriptHandler?`              | `null`                     | Optional body appended to generated `main.js` after event/service imports. |

## Basic Usage

Override `ItemEvents` on your item class. Each property is a `ScriptHandler` containing the **body** of a JavaScript event handler - the code inside the handler function, not a full function declaration:

```csharp
using ingot.Core.Behaviour.Item;
using ingot.Core.Common;

public class MagicWandItem : Item
{
    public override Identifier Identifier => new("mynamespace:magic_wand");
    public override string Texture => "magic_wand";
    public override string DisplayName => "Magic Wand";

    public override ItemEvents? ItemEvents => new()
    {
        UseEvent = """
            const player = event.source;
            player.sendMessage("You waved the wand!");
            """,
        UseOnEvent = """
            const block = event.block;
            event.dimension.playSound("random.orb", block.location);
            """
    };
}
```

### File-based handlers

```csharp
using ingot.Core.Scripting;

public override ItemEvents? ItemEvents => new()
{
    UseEvent = ScriptHandler.FromFile("./scripts/items/magic_wand_use.js"),
};
```

> [!TIP]
> The file should contain only the **handler body**, not a full function declaration or registration boilerplate.

```javascript
const player = event.source;
player.sendMessage("You waved the wand!");
```

Register and compile as usual:

```csharp
using ingot.Core;

const string packUuid = "77f1fef2-bb39-411a-b25c-ae475c21169f";

Pack pack = Pack.Create(packUuid, "My Addon", "Items with script events")
    .AddItem<MagicWandItem>();

pack.ScriptsEnabled = true;
pack.Compile("./output");
```

## What Gets Generated

For an item with identifier `mynamespace:magic_wand` and at least one event handler, **ingot** produces three things:

### 1. Custom component in item JSON

An empty component is added to the item's `components` object. The component id is derived from the item identifier (namespace is included in both the id prefix and the name segment):

```
mynamespace:mynamespace_magic_wand_item_events_component
```

```json
"components": {
    "mynamespace:mynamespace_magic_wand_item_events_component": {}
}
```

### 2. Per-item JavaScript file

A script file is written under the behaviour pack:

```
bp/scripts/items/mynamespace_magic_wand_events.js
```

This file registers the custom component at startup:

```javascript
// autogenerated by ingot
import { system } from "@minecraft/server";

const MynamespaceMagicWandItemEventsComponent = {
    onUse(event) {
        const player = event.source;
        player.sendMessage("You waved the wand!");
    },
    onUseOn(event) {
        const block = event.block;
        event.dimension.playSound("random.orb", block.location);
    },
};

system.beforeEvents.startup.subscribe(({ itemComponentRegistry }) => {
    itemComponentRegistry.registerCustomComponent(
        "mynamespace:mynamespace_magic_wand_item_events_component",
        MynamespaceMagicWandItemEventsComponent
    );
});
```

### 3. Updated `main.js` entry point

**ingot** writes `bp/scripts/main.js` with imports for your configured Script API modules, [services](../script-services.md), and every generated item event script:

```javascript
// autogenerated by ingot
import {world, system} from "@minecraft/server";
import "./items/mynamespace_magic_wand_events.js";
```

Extra modules in `ScriptApiModules` (for example `@minecraft/server-ui`) are namespace-imported in the per-item event script so handler bodies can use them (`import * as serverUi from "@minecraft/server-ui"`). In `main.js` they are bare-imported only. If you replace the whole `ScriptApiModules` dictionary and omit `@minecraft/server`, ingot re-adds `@minecraft/server` 2.8.0 when writing scripts. Prefer indexer assignment so existing modules stay. See [Block Events - script modules](../block/block-events.md) for a full example.

The behaviour pack manifest references `scripts/main.js` as the script module entry when scripts are present.

## Available Events

Each `ItemEvents` property maps to a Script API custom component event name. Set a property to `null` (or omit it) to skip that handler.

| C# Property                  | Script API Event           | Notes |
|------------------------------|----------------------------|-------|
| `BeforeDurabilityDamageEvent`| `onBeforeDurabilityDamage` | Fires when the item is about to take durability damage from hitting an entity. |
| `CompleteUseEvent`           | `onCompleteUse`            | Requires `minecraft:use_modifiers` to trigger reliably. |
| `ConsumeEvent`               | `onConsume`                | Requires `minecraft:use_modifiers` and `minecraft:food` to trigger reliably. |
| `HitEntityEvent`             | `onHitEntity`              | Fires when the item is used to hit another entity. |
| `MineBlockEvent`             | `onMineBlock`              | Fires when the item is used to mine a block. |
| `UseEvent`                   | `onUse`                    | Fires when a player uses the item. |
| `UseOnEvent`                 | `onUseOn`                  | Fires when the item is used on a block. |

Handler bodies are inserted verbatim into the generated JavaScript. Use valid Script API syntax and the `event` parameter provided by each hook.

## Pairing Events with Traits

Some Script API events only fire when the item also has the matching vanilla component. Add the appropriate [trait](../advanced/trait-system.md) on your item class:

```csharp
using ingot.Core.Behaviour.Item;
using ingot.Core.Common;
using ingot.Core.TraitSystem.Traits.Item;

public class HealingBerryItem : Item, IFood, IUseModifiers
{
    public override Identifier Identifier => new("mynamespace:healing_berry");
    public override string Texture => "healing_berry";
    public override string DisplayName => "Healing Berry";

    public override ItemEvents? ItemEvents => new()
    {
        ConsumeEvent = """
            event.source.applyEffect("regeneration", 5, { amplifier: 1 });
            """
    };

    // IFood
    int IFood.Nutrition => 4;
    float IFood.SaturationModifier => 0.6f;

    // IUseModifiers
    float IUseModifiers.MovementModifier => 0.35f;
    dynamic? IUseModifiers.StartSound => "random.eat";
    float IUseModifiers.UseDuration => 1.6f;
}
```

Common pairings:

| Event property       | Recommended trait(s) | Component |
|----------------------|----------------------|-----------|
| `CompleteUseEvent`   | `IUseModifiers`      | `minecraft:use_modifiers` |
| `ConsumeEvent`       | `IFood`, `IUseModifiers` | `minecraft:food`, `minecraft:use_modifiers` |

> [!IMPORTANT]
> ingot emits compile-time warnings when an event handler is configured without its recommended trait. It does **not** auto-add traits.

## How Compilation Works

Script generation is a dedicated pass after behaviour-pack JSON is written. See [Block Events](../block/block-events.md#how-compilation-works) for the full pipeline.

## Tips & Gotchas

- `ItemEvents` is a `struct`. Use `new()` with an object initializer as shown above.
- Only properties you set are included in the generated component.
- Each item with events gets its own `.js` file and its own custom component id.
- `scripts/main.js` is regenerated from events, [services](../script-services.md), and module imports.
- Enable `pack.Compile("./output", verbose: true)` to see script messages and trait warnings in `ingot.log`.
